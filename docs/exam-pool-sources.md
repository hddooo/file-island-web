# 실전 모의 확장 풀 — 근거와 한계

실전 모의 탭에서 한국사능력검정시험 심화 **제70–79회 실제 문항 500개**(10회 × 50문항)를 풀 수 있게 한 작업의 출처·방법·수·한계를 적는다.
이 문서는 사람이 쓴 기록이다. 수는 생성기(`scripts/build_exam_pool.py`)가 원문 데이터에서 세어 `media/exam-pool.js`·`docs/exam-pool-map.json`에 쓴다. 두 파일이 이 문서와 다르면 생성 파일이 맞다.

## 1. 입력(저장소 밖, 조정자가 원본 PDF에서 뽑은 읽기 전용 산출물)

| 파일 | 쓰는 곳 |
| --- | --- |
| `hanq-exam-normalized-source.json` | 500문항의 회차·번호·원본 PDF·쪽·자른 영역·공식 정답·배점·분류(주 시대·관련 시대)·contentVersion |
| `hanq-local-exam-answer-audit.json` | 공식 정답 PDF 10개에서 다시 읽은 정답·배점. 생성기가 위 파일과 한 문항씩 대조 |
| `hanq-exam-negative-and-point-source-audit.json` | 회차별 배점 합(모두 100) · ‘옳지 않은/적절하지 않은’ 꼴 **후보** ID 40개 |
| `hanq-exam-analysis/question-image-manifest.json` · `question-images/RR-NN.webp` | 문항 그림 500개의 SHA-256 · 원본 PDF · 쪽 · 픽셀 영역 |
| `hanq-exam-common-material-manifest.json` · `question-images/72-common47-48.webp` (선택) | 여러 문항이 함께 쓰는 공통 자료. 지금은 72회 [47~48] 하나: 원본 PDF 12쪽(원본 SHA-256 `87307e72…`)의 자른 영역(포인트 35,65–363.252,448 · 픽셀 70,130 657×766) · 그림 SHA-256 `777d3364c99fa96f84093ab2438587cdf3f4f3bdd0bdcdb4b2b0ee0f7eb04446` · 문항 72-47·72-48. 조정자가 원본 PDF 6개의 글자 상자와 스캔 48쪽 OCR에서 ‘[NN~NN]’ 공통 머리를 모두 찾아 이 한 쌍뿐임을 확인했다(`hanq-exam-common-material-source-audit.json`) |
| `hanq-existing-mock-55.json` | 예전 실전 모의 55문항 스냅숏. 앱의 `media/past-exam-quiz.js`와 같아야 생성기가 진행 |
| `hanq-full-textbook-original.txt` | 풀이 카드의 교재 근거 줄(쪽은 `\f`로 센 실제 PDF 쪽, 교재 쪽 = PDF − 7) |
| `hanq-exam-review-input/round-70…79.json` | 문항 글·보기 글 추출본(풀이 원고를 쓸 때 참고만, 화면 본문에는 쓰지 않음) |
| 강의 원고(선택) | 근거 행 번호만 남김. 받아쓰기 오타가 있어 화면에 옮기지 않음 |

생성기는 입력 폴더를 밝혀야 실행된다(`python3 scripts/build_exam_pool.py <입력 폴더> [강의 원고]` 또는 `HANQ_EXAM_SOURCE_DIR`). 없으면 종료 코드 2로 멈춘다. 시간·난수·개인 경로를 쓰지 않으므로 같은 입력이면 같은 출력이 나온다.

## 2. 무엇을 만드는가

- `media/exam-pool.js`: `window.HANQ_EXAM_POOL`. 문항 ID `exam-RR-NN`, 보기 ID `exam-RR-NN-option-k`(k = 원래 보기 번호 1–5). 시대별 풀(예전 기본 문항 먼저 → 주 시대 → 관련 문항), 세트 수 = ⌈풀/20⌉.
- `media/exam-expanded/RR-NN.webp`: 예전 55문항이 아닌 **445문항**의 원본 자른 그림을 편집 없이 복사(SHA-256 확인). 예전 55문항은 `media/exam/`의 그림을 그대로 쓴다.
- `media/exam-expanded/72-common47-48.webp`: 공통 자료 그림 1개(입력 그림을 SHA-256 확인 뒤 그대로 복사). 그래서 `media/exam-expanded/`의 그림은 445 + 1 = 446개다. 72-47·72-48 두 문항에만 `commonImage` · `commonImageSha256` · `commonLabel` · `commonQuestionIDs` · `source.commonMaterial`(원본 PDF·SHA·쪽·자른 영역)이 붙는다. 두 문항의 ID·정답·배점·문항 그림·contentVersion은 그대로다. 같은 필드를 뒤에 붙일 오답 노트·개인 모의도 그대로 쓸 수 있다.
- `docs/exam-pool-map.json`: 입력 해시 · 수 · 시대별 문항 ID · 분류 메모 · ‘옳지 않은’ 꼴 후보와 실제 표시 · 근거 없는 연도(`unsourcedYears`) · 그림 공백(`imageSourceGaps`, 지금은 없음) · 공통 자료(`commonMaterials`) · 근거 범위.

예전 55문항의 데이터(`media/past-exam-quiz.js`)와 그림(`media/exam/`)은 바꾸지 않는다. 확장 풀은 같은 ID로 이어 붙이고 예전 풀이(topic · why · remember)를 ‘예전 풀이’로 함께 보인다.

## 3. 수 — 실제 10회분에서 센 수(예측이 아니다)

주 시대별 문항 수(500 = 합계, 한 문항은 주 시대 하나):

| 시대 | 문항 |
| --- | ---: |
| 선사시대 | 10 |
| 고조선과 여러 나라 | 12 |
| 삼국시대 | 38 |
| 남북국시대 | 30 |
| 고려 시대 | 86 |
| 조선 전기와 양난 | 44 |
| 조선 후기 | 49 |
| 개항기와 대한제국 | 71 |
| 일제 강점기와 독립운동 | 86 |
| 광복과 대한민국 | 56 |
| 통사·복합 | 18 |

- 조선시대(전기 + 후기) = 93.
- **76-02**는 고조선과 여러 나라로 분류했다(그래서 고조선과 여러 나라 12 · 삼국 38). 분류 메모(`classificationNote`)를 문항에 남긴다.
- **독도와 간도**는 주 시대 문항이 없고, 관련 지역·독립운동 문항 10개(예전 5 + 71-24 · 73-36 · 74-41 · 72-37 · 70-37)를 ‘관련’으로 묶는다. 화면에는 ‘관련 지역·독립운동’이라고 표시한다.
- **통사·복합 18문항**은 새 학습 시대를 만들지 않고, 실전 모의 범위 ‘통사·복합’이나 ‘전체 500’으로만 푼다.
- 이 수는 출제 빈도의 근거로 쓰는 **실제 지난 10회분의 수**이고, 앞으로 무엇이 나올지에 대한 예측이 아니다.

## 4. 풀이 원고(`docs/exam-reviews/round-RR.json`)

문항마다 카드 하나(정답 · 왜 · 결정 단서 · 흐름 · 외울 말 · 헷갈림)와 **원래 보기 번호 다섯 개 모두의 짧은 풀이**를 쓴다. 생성기는 원고에 50문항이 모두 있고 보기 풀이가 다섯인지 확인한다.

쓴 방법:
- 문항 글·보기 글 추출본을 읽되, **순서·연표·그림·지도·자료 보기는 원본 문항 그림을 직접 보고** 확인했다. 추출본의 그림 이름(문화유산 이름)은 사실이 아니라 관찰 기록으로 다뤘다.
- 조정자가 교재 그림과 직접 대조한 이름(예: 70-27 ⑤ 강세황 영통동구도, 73-06 ⑤ · 76-04 ③ 호우명 그릇, 78-09 ⑤ 경주 구황동 금제여래좌상, 70-27 ③ · 76-27 ① 김득신 파적도)은 그대로 따랐다.
- 그림만으로 이름을 확정할 수 없는 보기는 이름을 지어 쓰지 않고 그림 속 모습으로 적고(예: ‘철제 갑옷 모양 유물’, ‘벽돌 모양 다층탑’), 이 문항에서 왜 답이 아닌지만 밝혔다.
- ‘옳지 않은/적절하지 않은’ 꼴은 감사 파일의 후보 40개를 그대로 믿지 않고 문항 그림·글을 보고 정했다. 원고에서 `neg`로 표시한 문항은 31개(70-22·25·48 · 71-16·26·44 · 72-04·27·42·44 · 73-08·19·30·41 · 74-13·26·29·40·41·50 · 75-26 · 76-26·41·43·46·50 · 77-13·23 · 78-25·43·47)이고, 카드 ‘왜’에 그 꼴을 밝히고 정답 보기는 ‘사실과 맞지 않는 진술’로 설명한다. 이 31개는 감사 파일의 질문 머리 확인 목록(`negativeStemConfirmedIDs`, 띄어 쓴 ‘적절 하지 않은’의 76-26 포함)과 정확히 같아야 하고, 다르면 생성기가 멈춘다. 지문 안의 부정 표현까지 잡은 넓은 후보 40개(예: 76-24·76-29)는 부정형 문항이 아니다.
- 흐름(ctx) 줄의 화살표(→)는 앞뒤가 확인된 순서에만 쓴다. 같은 시기의 여러 일은 ‘·’로 나란히 둔다(예: 몽골 항쟁기의 처인성·팔만대장경 조판·충주성, 거란 침입기의 초조대장경·나성, 광무개혁의 양전·원수부·지계, 1920년대의 회사령 폐지·산미 증식 계획·물산 장려·민립 대학).
- 연도: 원고에 연도를 쓰면 그 연도가 문항 글·교재·흐름 카드·강의 원고·예전 풀이 중 하나에 있어야 한다. 없으면 생성기가 `unsourcedYears`에 남기고 검사기가 실패시킨다. 그래서 원고는 연도 대신 왕·시기·앞뒤 관계로 주로 설명했다.

## 5. 알려진 한계 — 사람 확인이 필요한 곳

1. **72-47 · 72-48 공통 자료(해결됨)**: 두 문항의 문항 그림(띠)에는 [47~48] 공통 지문이 들어 있지 않다. 조정자가 원본 PDF 12쪽에서 공통 자료 전체((가)~(라) 네 단락, 답 표시 없음)를 따로 잘라 냈고, 화면은 두 문항 모두 **공통 자료를 문항 그림보다 먼저** 보이며 ‘크게 보기’에도 두 그림을 함께 싣는다. 그래서 예전의 ‘자료 빠짐(sourceGap)’ 안내는 없앴다(원고에 남아 있으면 생성기가 멈춘다). 풀이 내용((가) 신문왕 관료전·녹읍 폐지 · (나) 전시과 · (다) 과전법 · (라) 세조 직전법)은 이 공통 자료와 같다. 다른 회차에는 명시된 공통 지문 머리가 없다는 것이 조정자 감사 결과다.
2. **그림 보기 이름 — 확인한 것과 못 한 것**
   - 교재 그림(교재 PDF 18·21·24·33·36·54·77·79쪽 문화유산 사진)과 문항 그림을 직접 맞대어 이름을 적은 보기: 71-07 ①–⑤(화엄사 사사자 삼층 석탑·정림사지 오층 석탑·분황사 모전 석탑·발해 영광탑·석가탑), 72-17 ②(정림사지 오층 석탑), 77-13 ④(호우명 그릇 — 교재의 바닥 사진과 같음), 78-14 ①②④(정림사지 오층 석탑·발해 영광탑·양양 진전사지 삼층 석탑), 79-06 ③(발해 영광탑), 76-17 ①②③. 73-06 ①은 조정자가 원본을 다시 보고 충주 고구려비로 확인한 것을 따랐다. 79-41 ⑤는 공식 백과사전 근거로 김용관(발명 학회·과학 데이)으로 적었다.
   - 이름을 확인하지 못해 모습으로만 적고, ‘이 문항의 답이 아닌 까닭’만 밝힌 보기(남은 확인 대상): 72-23 ①③ · 73-06 ②③④ · 75-03 ③ · 76-04 ④ · 76-17 ④⑤ · 76-27 ②④ · 77-04 ③ · 78-26 ②③. 73-06 ④·77-04 ③은 보이는 대로 ‘고리가 달린 판 모양 청동 유물’이라고만 적고, 허리띠 장식이라는 이름은 근거가 없어 쓰지 않는다. 77-04 ④(정답)도 이름은 확인하지 못해 모습(새 날개 모양 금 장식)과 공식 정답으로만 설명한다. 예전에 적었던 ‘발해 삼채’ 같은 추정 이름은 쓰지 않는다. 76-27 ④를 기억만으로 김홍도 ‘점심’이라 부르지 않는다(공식 박물관 사진과 구도가 다름).
   - 추출본 이름이 그림과 맞지 않은 곳(79-06 보기 이름, 72-17 ②를 다보탑으로 적은 것, 73-26 ④를 세한도로 적은 것, 78-14 ①을 다보탑으로 적은 것)은 그림을 따랐다.
3. **OCR 회차(78·79회)**: 문항 글에 오탈자가 있어 원고는 그림을 기준으로 썼다. 화면 본문은 OCR 글이 아니라 원본 그림이다.
4. **원고는 사람이 쓴 설명**이다. 공식 정답·배점은 정답 PDF와 대조했지만, 풀이 문장의 사실은 교재·그림·일반 지식을 바탕으로 썼고 문항마다 공식 해설과 대조하지는 않았다. 내용 사실 확인(QA)이 필요하다.
5. 원고 작성 CLI에서는 생성기·검사기·브라우저를 실행하지 않았다. 조정자가 실행한 결과는 아래 독립 검증 절에 기록한다. `media/exam-pool.js`·`media/exam-expanded/`·`docs/exam-pool-map.json`은 생성기를 실행해야 생긴다. 실행 결과(근거 없는 연도·그림 해시·수)는 검사기 19번과 동작 검사로 확인한다.
6. 상업적 이용 권리는 이후에 따로 확인할 일이다.

## 6. 화면(앱)

- 실전 모의 탭: 범위(이 시대 · 통사·복합 · 전체 500) × 묶음(기본 = 예전 문항 · 20문항 세트(마지막 세트는 남은 수) · 전체) · 문제 바로 가기 · 처음/안 푼 문제/아무 문제로.
- 보기는 원래 번호 ①–⑤ 버튼(누르기 44px, 라디오, 방향키). 고르기만으로는 채점하지 않고 ‘정답 확인’ 뒤에만 풀이 카드와 보기 다섯 풀이(보기 ID별)를 보인다.
- 공통 자료가 있는 문항(72-47·72-48)은 ‘공통 자료 · 제72회 47~48번 공통 자료 (가)~(라)’ 제목과 대체 글이 붙은 공통 자료 그림을 문항 그림 앞에 보인다. 정답·풀이는 채점 전에 보이지 않는다.
- 문제 그림 ‘크게 보기’는 대화 상자(Escape · 닫기 버튼으로 닫고 초점을 돌려줌). 공통 자료 문항은 공통 자료와 문항 그림을 차례로 함께 보인다. 홈·단계 이동·뒤로 가기·주소(해시) 변경 때도 닫히며, 그때는 새 화면 제목(홈이면 홈 버튼)에 초점을 둔다. 크게 보기 버튼은 누르기 높이 44px.
- 저장·계정·서버 없음. 고르기·채점 때 `hanq:mock` 이벤트만 알리고, `window.HanqMock`으로 읽기 전용 상태를 낸다.
