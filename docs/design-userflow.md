## 얼음섬

**사이트 전체 대전 초대 (서버 지원 시에만, 현재 운영 API 배포 대기):** 로그인한 사용자는 마이페이지·단어장·한국사·영어섬·랭킹 등 어느 화면에서든 신청을 받는다. 화면 가운데에 `○○님이 대전을 신청했습니다. 수락하시겠습니까?`와 남은 시간, 수락/거절이 뜨고, 수락 전에는 화면 이동·전투 시작이 없다. 거절·만료·취소 때 지금 화면(입력·답·타이머·스크롤)은 그대로다. 여러 신청은 팝업 하나에 `뒤에 N개의 신청이 더 있어요`로 정리하고 각자의 만료 시각을 지킨다. 신청자는 `○○님에게 대전을 신청했습니다. 상대 수락을 기다리는 중입니다.`와 남은 시간·신청 취소를 본다. 거절·취소·만료·상대의 다른 전투 시작·접속 종료는 양쪽에 짧은 안내로 알린다. 수락할 때 저장되지 않은 학습 내용은 기존 저장·이탈 확인을 먼저 거치며, 확인 중 신청이 만료되면 전투에 들어가지 않는다. 얼음섬 목록은 HanQ에 접속한 모든 로그인 사용자를 `대전 가능`(얼음섬) · `학습 중`(다른 화면) · `초대 응답 대기` · `○○님과 전투 중`으로 보이고, 내 줄은 `나`로 구분하며 신청 버튼이 없다. 전투 중 상대에게는 신청할 수 없다(서버가 거절). 기존 API에서는 이 기능이 꺼져 있고 지금처럼 얼음섬 입장자만 보인다.

제목 옆 작은 불빛이 실제 대기실 연결 상태를 보여준다: 파랑 연결됨 · 노랑 연결 중/재연결 중 · 빨강 연결 끊김(색과 함께 ✓/…/! 기호). 정상 상태 문구(`대기실에 연결됐어요` 등)는 화면 문장으로 띄우지 않고, 불빛에 hover·키보드 focus·tap하면 설명이 열린다. 연결 끊김 안내와 `다시 연결` 버튼 등 행동이 필요한 오류는 그대로 화면에 남는다.

1. 대기실에서 과목 선택. 목록은 활성 화면에서10초마다, 과목 변경 즉시, 새로고침 아이콘으로 갱신한다. TOEIC에만 연습 상대가 있다.
2. 대결 신청·수락 → 양쪽 몬스터 위 Ready → 처음 한 번 준비 → 중앙3·2·1. 시작 전 방 나가기는 XP 없는 취소이고 시작 후 도주는 패배다.
3. 짙은 문제 모달에서 답을 바꿀 수 있다. 제출할 때 확정하며 접수 뒤 완료를 표시한다. 양쪽 제출/마감 전 정답을 미리 공개하지 않는다.
4. 판정 공개 → 문항별 ○/X → 문제 모달 닫힘 → 공격/회피/상쇄·HP 변화 →3·2·1→자동 다음 문제. 연습 상대는 본인의 묶음 답이 모두 제출되면 인위적인 상대 대기 없이 판정한다.
5. HP0/도주 등 종료 → Victory/Defeat 또는 무효 모달·실제 XP → 확인 → 통계·내 답·정답·기존 해설. 없는 원문을 확인된 자료처럼 생성하지 않는다.
6. MyPage → 내 배틀 기록 → 복기하기. 오답노트 최상단0. 전투 오답에서 본인 오답을 재풀이한다. 재열람으로 XP를 재지급하지 않는다.

LC는 양쪽 준비 후 같은 서버 시각에 시작하며 음원 재생시간+5초가 마감이다. OS 오디오 중단을 앱이 완전히 막는다고 보장하지 않는다. [서버 타이머·정산 설계](https://github.com/blockmonkey1992/hanq_api/blob/dev/docs/design-development.md)를 기준으로 한다.

## 마이페이지 · 나의 기록 (10/28)

캐릭터 왼쪽 위에서 누적 출석과 출석 행동을 함께 확인한다. 캐릭터·성장 기록 조작은 유지한다. 출석 조회 중·미확인·오늘 완료 상태에서는 중복 제출하지 않고, 실패하면 버튼에서 다시 시도할 수 있다. 성공 후에는 출석 상태 안내로 키보드 초점을 돌린다.

계정 설정 아래에는 `나의 기록`과 `내 문의`를 구분해 표시한다. 공부 달력의 `함께 / 역사숲 / 토익해변`은 `전체 / 역사섬 · 한국사 / 영어섬 · 토익`으로 표시한다. 이곳의 `함께`는 전체 과목 필터였으며 커뮤니티 기능이 아니다.

문제별 기록은 과목·풀이 경로로 거르고 20건씩 조회한다. 실제 재풀이는 별도 행이다. 문제 내용·정오답·한국 시간·저장 유형을 확인하고 `문제·해설 상세 보기`를 펼친다. 저장된 진입 경로가 없으면 `경로 미확인`, 문항별 시각이 없는 배틀은 `풀이 시각 미확인`과 라운드 시작 시각을 구분한다. 기존 배틀 전체 복기와 한국사 오답·모의고사 상세 경로도 남긴다. 필터 변경은 첫 페이지, 뒤로 가기·새로고침은 URL에 저장된 필터·페이지·조회 시각을 복원한다.

## 연속 출석 퀘스트

출석 보상은 KST 달력 기준 하루 한 번, 연속 출석 순서로 `10→20→30→40→50→10`을 반복한다. 하루라도 빠지면 다음 출석은 10XP다. 가입·로그인의 기존 자동 출석에도 같은 규칙이 적용된다. 과거 출석이나 기존 10XP를 소급 정산하지 않는다.

캐릭터 왼쪽 위의 5칸 체크판은 완료·오늘·예정을 구분한다. 실제 전체 연속 일수와 이번 5일 보상 주기 진행률은 별도로 표시한다. 5일차를 완료한 당일에는 지급한 50XP 칸을 유지하고, 다음날 새 주기 10XP로 돌아간다고 안내한다. 이전 정책의 완료 칸은 실제 과거 지급액을 표시한다. 모바일·태블릿은 체크판이 캐릭터와 겹치지 않게 흐름 안에 배치한다. 키보드 제출, 완료 안내 초점, 화면 읽기용 상태와 축소 모션을 지원한다.

## 얼음섬 수락·수동 진화 후속 (서버 배포 상태 구분)

대결 신청자는 중앙의 상대 수락 대기 팝업에서 남은 시간과 신청 취소를 확인한다. 수신자는 `○○님이 대전을 신청했습니다. 수락하시겠습니까?` 모달에서 수락/거절한다. 수락 전에는 전투 장면을 렌더링하지 않는다. 여러 요청은 한 모달씩 보여주고 새 요청이 와도 현재 읽는 상대를 바꾸지 않는다. 만료시각은 서버 expiresAt을 사용하며 초대 카운트와 문제 풀이 30초는 별도다.

새 API에서는 초대 10초, 얼음섬 탭별 입장 lease, 대기/`○○님과 전투 중입니다.` 표시, 한국사·TOEIC 연습봇이 제공된다. 봇은 실제 회원 목록과 분리되어 표시되며 XP 변동이 없다. MyPage 진화 버튼은 서버 형태와 다음 임계값을 기준으로 활성화되고, 한 클릭은 한 단계만 진행한다. 초과 XP는 유지한다. 출석판 문구와 이전 메뉴 리뉴얼은 보존한다.

배포 호환성: 현재 서버가 partnerEvolution을 반환하지 않으면 새 세션·진화·한국사 봇 API를 호출하지 않는다. 이때 기존 pending/accept/decline만 사용해 중앙 수락/신청자 대기 모달을 제공하고 기존 서버 만료(30초)를 그대로 표시한다. 10초 제한·여러 초대·정확한 입장·수동 진화·한국사 봇의 운영 완료는 새 API 배포 확인 뒤에만 선언한다. 서버 계약은 [API 설계](https://github.com/blockmonkey1992/hanq_api/blob/dev/docs/design-development.md)를 따른다.

## 무지개섬 · 디지몬 보관함

무지개섬은 그림 자체가 게임 장면이다. 기존 배경·레일·곰·알 그림을 유지하고 노란 곰 수호자와 작은 곰들이 잔디 안쪽의 서로 다른 동선을 순찰한다. 수호자는 기존 노란 곰의 색·배·얼굴을 유지한 3프레임 걸음 그림으로 이동하고, 두 서비스 정차점에서는 중립 자세로 쉰다. 작은 곰도 멈춤·이동 방향·지면 깊이를 따른다. 발 디딤·지면 그림자·원근 위치를 맞추고, 기차는 기존의 배경별 레일 중심선과 앞뒤 레이어를 따른다. 모션 축소와 숨김 탭에서는 이동을 멈춘다. 캐릭터 고유 명칭을 추정해 확정하지 않는다. 한 장면 안의 왼쪽 `알 판매점`은 0 Coin 알을 실제 구매하는 공간, 오른쪽 `옷·스킨 판매점`은 곰인형들이 준비하는 천막 가게로 구분한다. 두 공간은 그림 아래 카드 목록으로 나누지 않고 잔디 지면과 곰의 동선 안에 배치한다. 옷 가게를 누르면 준비 중 안내만 열리고 거래 요청은 보내지 않는다.

장면의 알 클릭 → 정보와 `0 Coin · 구매 확인` → 서버 구매 확인 → 별도 `OOO 알을 구매 완료했습니다.` 창 → My Page 디지몬 보관함 흐름이다. 서버가 `partners.purchaseEnabled`와 `hatchEnabled`, 0 Coin 상품을 확인해 줄 때만 구매를 연다. 같은 진화 계열은 한 번만 구매한다. 통신 결과를 잃으면 같은 요청 번호로 다시 확인하며 클라이언트에서 지급을 만들지 않는다. Coin은 XP와 별개로 표시하고 현재 상품은 모두 0 Coin이다.

My Page는 장착 캐릭터 아래 디지몬 보관함에서 보유 개체의 개별 XP·알/부화 상태·현재 장착을 한눈에 보여준다. `알 꺼내기`로 처음 장착한 서버 시각부터 60초 뒤 자동 부화한다. 화면의 카운트다운은 서버 시각과 단조 시계의 경과량으로 표시하며, 실제 부화는 서버를 다시 확인한 뒤에만 반영한다. 새로고침·화면 이탈·나중의 재접속에도 시작·완료 시각은 서버에 유지된다. 부화가 확인되면 껍질이 갈라지는 연출을 한 번 보인다. 알의 수동 부화/100 XP 조건은 없다. 부화 후 한 단계 진화는 기존 XP 임계값과 서버 revision을 따른다.

XP는 장착한 한 마리에게만 쌓이며 계정 합계는 보유 개체의 합계다. 기존 첫 파트너와 누적 XP는 보존하고 새 알은 0 XP다. 대전 신청/전투 중 장착·진화는 서버 판정에 따라 막는다. `옷장 · 준비 중`은 `디지몬을 꾸밀 새로운 옷장을 준비하고 있어요!` 안내만 열며 옷/스킨 구매·장착 기능은 제공하지 않는다. 기존 공부 달력과 간결한 기록 목록은 보관함 아래에 유지한다.

무지개섬도 로그인 검사는 유지한다. 무지개섬 주소에서 로그인하거나 섬에서 세션이 만료되어 다시 로그인하면 섬으로 돌아온다. 명시적 로그아웃 뒤 새 로그인은 지도로 간다. 로그인 유지 지원을 확인할 수 없는 서버/브라우저에서는 옵션과 이유를 보여주되 선택을 막는다. 일반 로그인은 그대로 이용한다. 지원 거절 응답 뒤에는 `일반 로그인으로 다시 시도`를 직접 눌러야 하며 비밀번호를 자동으로 다시 보내지 않는다.

## 설치 앱 업데이트

새 배포를 확인하면 작은 안내에서 `새 버전 적용` 또는 `나중에`를 선택한다. 풀이/대결 중에는 메인 메뉴로 돌아와 적용하라는 안내만 나오며 강제로 끊지 않는다. 음원을 멈추고 입력/저장을 마치면 적용할 수 있다. 적용 후 현재 메뉴와 로그인 복원, 기존 학습 저장 내용을 유지한다. 연결 실패 때는 현재 화면을 계속 사용한다. 이 안내가 없던 옛 설치 앱에 새 코드가 처음 도달하는 단계는 실물 iPhone에서 아직 검증하지 않았다.


## 간단한 건의·문의 · 0.4.18-beta

지도에서 `건의·문의`를 누르면 독립 `/inquiries/` 페이지를 연다. 제목·내용·보내기만 있는 기존의 간결한 UI 위에 3문장 안내를 두고, 7일 이내 가입한 이메일로 답변드린다고 안내한다. 로그인 전에는 메인의 로그인 링크를 제공하며, 로그인한 뒤 문의 페이지를 다시 열도록 안내한다. MY PAGE의 기존 작성 모달과 문의·답변 목록은 유지한다.

서버가 접수를 확인한 뒤에만 보냈다고 표시한다. 전송 중에는 중복 제출을 막고, 결과를 확인하지 못하면 원래 내용과 전송 번호를 유지해 같은 문의를 다시 확인한다. 문의 창이 자체 진행·결과를 표시하므로 공통 대기창을 겹쳐 띄우지 않는다. MY PAGE 모달의 취소·Escape·뒤로 이동은 창을 닫고 본문 잠금을 해제한다. 독립 페이지는 모달 잠금 없이 일반 페이지로 이동한다. 브라우저 뒤로/앞으로 캐시 복귀는 세션 확인 뒤 폼 또는 목록을 복원하며, 미확인 전송 번호는 같은 계정·로그인에서 유지한다.

MY PAGE의 `내 문의`에서 보낸 제목을 20건씩 보고 펼치면 본문과 관리자 답변을 확인한다. 관리자 답변이 없으면 아직 답변이 없다고 표시한다. ADMIN의 기존 문의함과 답변 작성 경로는 유지한다. 기존 문의·추가 메시지·답변·감사 기록, 인증과 본인/관리자 접근 제한은 변경하지 않는다. 로그아웃·계정 전환 뒤의 늦은 응답은 버리고 이전 계정의 화면과 임시 입력을 지운다.
