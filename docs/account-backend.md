# 계정·서버 연결(선택) — 앞단 동작

서버 코드는 형제 저장소 `../hanq_api`(NestJS + PostgreSQL, 스키마 `hanq`)에 있다. API는 `../hanq_api/docs/api.md`, 보안 경계는 `../hanq_api/docs/security.md`.

## 1. 서버 주소 · 켜고 끄기

- **배포 기본값**: `index.html`의 `<meta name="hanq-api-base" content="https://hanq-api.onrender.com">` — 배포된 HanQ API. 주소에는 경로를 넣지 않는다
  (`media/api-client.js`가 `/api/v1/…`을 붙인다. 실수로 `/api/v1`이나 끝 `/`를 붙여도 떼어 내 겹치지 않게 한다). 서버의 `HANQ_CORS_ORIGINS`에 배포된 앱 주소(`https://hanq.vercel.app`)가 정확히 있어야 한다.
  호스팅(Vercel) 설정은 바꾸지 않는다.
- **회원 퀴즈의 제출 답안은 서버에 저장**된다. 게스트 퀴즈·실전 모의의 기존 기기 기록은 직접 가져올 때만 보낸다.
- **오프라인 모드(의도적으로 끄기)**: `content=""`로 비우면 서버를 전혀 부르지 않는다. 학습 기록·오답노트·오답 다시 풀기·오답 모의고사는 이 기기에서만 돌고,
  목차의 ‘내 계정’ 버튼과 오답노트의 서버 안내도 나오지 않으며, `#account`는 ‘서버 연결 꺼짐 · 이 기기에서만 저장’ 안내만 보인다.
  이때 이 기기에서 도는 다시 풀기·모의고사는 연습용이며, 기록을 바꾸면 우회할 수 있으므로 **프리미엄을 지키는 장치가 아니다.**
- **개발용 바꿔 끼우기**: 페이지를 이 기기(`localhost` · `127.0.0.1` · `[::1]`)에서 열었을 때만 `localStorage['hanqdev.apiBase']`가 meta보다 앞선다(meta가 채워져 있어도).
  배포된 사이트(`*.vercel.app` 등)에서는 저장돼 있어도 **읽지 않는다**. 주소는 https 또는 `http://localhost` 계열만 받고, 아이디·비밀번호·쿼리·# 붙은 주소는 버린다(그때는 meta 사용).
- 검사기 `scripts/verify-hanq.cjs`의 동작 검사는 이 기기 전용 동작을 보므로 index를 오프라인 모드(meta 비움)로 열어 검사한다. 서버 쪽 동작은 `scripts/test-account-ui.cjs`(가짜 fetch, 실제 네트워크 없음)가 본다.

## 2. 켜져 있을 때(배포 기본)

- **로그인·회원가입·로그아웃·모든 기기에서 로그아웃·내 프로필(이름 바꾸기·비밀번호 바꾸기)**: `#account` 화면(`media/account-ui.js`). 목차의 ‘내 계정’과 오답노트 위 안내에서 들어간다.
- **토큰**: 접근 토큰은 이 탭의 메모리에만(`localStorage`·`sessionStorage`에 쓰지 않음). 갱신 토큰은 서버가 정한 HttpOnly 쿠키. 새로 고치면 쿠키로 조용히 다시 로그인한다.
  갱신은 Web Locks(`hanq:auth:refresh`)로 탭 사이에서 하나씩(같은 갱신 토큰을 두 탭이 동시에 쓰면 서버가 도난으로 보고 모든 세션을 끊기 때문).
- **회원 퀴즈**: 시대·부분·문제 묶음의 안정된 문항 ID와 버전으로 `/quiz/progress`를 읽고 첫 미풀이를 자동 선택한다. 보기 선택·열람은 저장하지 않는다. ‘정답 확인’으로 `/attempts` 제출이 성공한 문제는 정오답과 무관하게 푼 것으로 센다. 조회·저장 실패 때 로컬 답으로 서버 완료를 대신하지 않는다. 같은 답안 재시도는 같은 제출 ID를 사용하고 계정 변경 시 이전 요청과 답안을 섞지 않는다.
- **완료·복습**: ‘다시 풀기’는 임시 답안을 새로 시작하며 기존 DB·기기 풀이 이력은 지우지 않는다. 오답노트 복습과 프리미엄 권한은 그대로다. 게스트는 기존 무료 기기 학습 범위만 사용하며 로그인 시 과거 기기 기록을 자동 업로드하지 않는다.
- **서버에 남는 기록**: 회원 퀴즈 제출, 직접 누른 기기 기록 가져오기, 서버 프리미엄 오답 다시 풀기·오답 모의고사. 실전 모의는 기존 기기 저장을 유지한다.
- **서버 풀이 기록**: 위 두 가지로 서버에 남은 내 풀이, ‘더 보기’로 페이지 넘김.
- **서버 오답노트**: 서버에 남은 내 채점 기록으로 계산한 못 푼 오답 / 해결 / 지금까지 틀린 문제(이 기기의 나만의 오답노트와는 따로다).
- **프리미엄(1개월 5,000원, 자동 갱신 없음)**: 상태·만료(한국 시간)·기간 기준(운영자 확정 전)을 보인다.
  실제 결제 연결은 아직 없다. 서버가 결제를 준비하지 않았으면 ‘온라인 결제는 아직 준비 중 · 결제되지 않음’과 꺼진 버튼만 보인다.
  서버가 **개발용 테스트 결제**를 켰다고 알려 줄 때만 ‘개발용 테스트 결제 — 실제 결제가 아니에요’ 상자와 테스트 버튼이 나온다(운영 서버에서는 서버가 켤 수 없다).
- **오답 다시 풀기·오답 모의고사(프리미엄)**: 서버가 문제를 고르고(정해진 수의 줄), 답을 저장하고, 시간을 재고, 채점한다. 화면은 서버의 결과를 그리기만 하고 정답·풀이는 채점 뒤에만 보인다.
  이 기기의 회차 컨트롤러(`media/run-controller.js`)는 서버 회차에 쓰지 않는다. 프리미엄이 없으면 버튼이 꺼지고, 버튼을 우회해도 서버가 거절한다(403).
- **나만의 오답노트(이 기기)**: 목록·풀이 보기는 그대로. 서버가 켜져 있으면 **새** ‘다시 풀기’와 ‘오답으로 모의고사 만들기’는 계정 화면(로그인 + 프리미엄)으로 보낸다.
  이미 이 기기에서 풀던 다시 풀기·모의고사는 지우지 않고 그대로 이어 풀 수 있다.
- **이 기기 기록 자동 동기화(media/account-sync.js)** — 예전의 수동 ‘가져오기’ 화면은 없앴다. 로그인·쿠키 복원으로 서버가 계정을 확인하면(마이페이지 밖에서도)
  그 계정으로 푼 기록만 500건씩 보낸다. 맞음 여부·점수는 보내지 않고 서버가 다시 채점하며, 이용권·성장점수는 생기지 않는다.
  - **소유 한계(중요)**: 예전 기록과 로그인하지 않고 남긴 기록에는 누가 풀었는지 남아 있지 않다. 그래서 어느 계정에도 자동으로 보내지 않고 이 기기에 그대로 둔다
    (첫 로그인 계정에 붙이지 않음). 새 기록은 앱의 hpRecord가 서버 확인 로그인(signedIn · ownerId = user.id)일 때만 `ownerId`를 붙이고, 그 계정과 정확히 같은 기록만 보낸다.
    시간제 회차(source 'run')·순위 기록·답하지 않은 기록은 보내지 않는다. 원본 기록은 지우거나 고치지 않는다.
  - 계정별 무작위 키 `hanqacct:ikey:<계정>`(예전 공용 `hanqacct:importKey`와 별개)와 확인 표시 `hanqacct:sync:<계정>`. 저장소를 쓸 수 없으면 보내지 않는다.
  - 서버 ID는 계정 + localId(`scope:'account'`)라 두 탭이 키를 따로 만들어도 한 번만 저장된다. 끝났다고 말하기 전에 내 최근 서버 기록(최대 5쪽)의 정확한 submissionId와
    비교한다(문제+답 비교 없음 — 같은 문제를 다시 푼 정상 기록이 있으므로). 보낼 것이 없어도 이 확인이 성공해야 ‘완료’. SubtleCrypto가 없으면 비교만 건너뛰고 서버 멱등 처리에 맡긴다.
  - 확인 표시는 서버 응답(imported/alreadyImported, 엄격 검사)으로 확인된 기록에만. 건너뛴 기록은 사유와 함께 보관·보고하고 다시 보내지 않는다. 실패한 묶음은 표시 없이 다음에 같은 ID로 다시 보낸다(자동 반복 없음).
  - 한 계정·한 로그인에 한 흐름(탭 안 Promise · navigator.locks). 계정 + 로그인 번호(epoch) + 세대가 바뀌면(A→B→A, 같은 계정 로그아웃→로그인) 이전 흐름은 아무것도 쓰거나 알리지 못한다.
  - 상태 한 줄과 실패 때 ‘다시 보내기’는 마이페이지 ‘계정 설정’ 안에 있다.
- **마이페이지(최소)**: 캐릭터(실제 진화 단계) · 닉네임 · 지금 성장점수(한 번, 누르면 성장점수 기록 창: 날짜·사유·부호 있는 점수, 20개씩 더 보기, Esc·닫기·바깥 누름, 닫으면 점수 단추로 포커스)
  → 출석 → 닫힌 계정 설정. 프리미엄 안내·테스트 전환·오답노트·풀이 기록은 오답노트 화면에 그대로 있다. 로그아웃은 헤더의 단추 하나(모든 기기 로그아웃 화면 단추는 없앴고 서버 API는 그대로).
  /me를 못 받으면 점수·캐릭터를 지어내지 않는다. 기록 창은 쪽 전체를 검사해 이상한 쪽은 한 줄도 붙이지 않는다.
- **로그인한 회원의 퀴즈·기출은 이용권과 상관없이 서버에 저장**(일반 회원은 기존 무료 5문항, 범위·권한은 서버가 확인). 저장 실패 때 이 기기 기록으로 바꾸지 않고 같은 답으로 다시 저장한다. 게스트만 이 기기에 저장.
- 성장점수 기록 창: 오답노트 도전·CBT 줄은 서버가 그 회차를 채점할 때 저장한 최종 결과(`examResult {score, maxScore:100, correct, total}`)를 “45/100점 · 9/20문항 정답 → 성장점수 -100점”처럼 함께 보여 준다. 정수 네 칸·범위·사유(오답노트/CBT만)·CBT 50문항을 엄격히 검사해 하나라도 어긋나면 그 쪽 전체를 버린다. `examResult`가 없거나 null(예전 기록·미완료·서버 검사 실패)이면 원래 사유만 보여 주고 점수를 짐작하지 않는다.
- 오답 복습 결과 화면·완료한 오답 복습 기록·CBT 결과/내 시험 기록도 저장된 `run.score.examScore`/`questions`/`correct`/`growthReward`, `result.score`/`correct`/`total`/`growthReward`만 쓴다. 예전처럼 정답 수로 시험점수를 계산하지 않고, 차감·보상 이유(60점 미만 −100 등 구간)를 함께 적는다.
- 이 화면들을 쓰려면 API 배포(`GET /api/v1/me/growth-history`, 가져오기 `scope:'account'`·상한 계산)가 따로 필요하다. 새 migration은 없다.
  이 기기의 기록은 지우거나 바꾸지 않고, 가져와도 이용권·보상은 생기지 않는다.

## 2-1. 계정이 바뀔 때·연결이 끊길 때

- 모든 로그인 요청은 응답이 도착했을 때도 **요청을 시작한 계정이 지금 계정인지** 확인한 뒤에만 결과를 넘긴다. 그 사이 이 탭에서 B로 로그인(또는 로그아웃)했으면
  늦게 온 A의 성공 응답(예: `/me`, 이름 바꾸기 결과)도 `session_changed`로 거절해 B의 화면 상태(사용자·이용권)를 덮어쓰지 않는다. 새로 고침 직후처럼 토큰 없이 갱신부터 할 때도 이미 알던 계정과 다르면 보내지 않는다.
  다시 풀기·모의고사의 답 저장·시작·제출·채점 결과도, 그 화면을 이미 떠났으면 화면을 다시 그리지 않는다(서버에는 저장됨).
- 같은 브라우저의 다른 탭에서 다른 계정(B)으로 로그인하면 갱신 쿠키가 B의 것이 된다. 이 탭에서 A로 시작한 요청이 401을 받아 갱신했는데 B가 돌아오면,
  그 요청을 B로 **다시 보내지 않고** `session_changed`로 멈춘다(A의 제출·이름 바꾸기가 B의 계정에 들어가지 않게).
- 계정이 바뀌면(로그아웃 포함) 이 화면이 들고 있던 이전 계정의 풀이 기록 목록·고른 답·제출 번호·프리미엄 표시를 버리고, 열려 있던 서버 다시 풀기·모의고사 화면은 닫고 알린다.
  내 계정 화면을 열 때마다 서버 풀이 기록의 첫 쪽은 지금 계정으로 새로 받는다(‘더 보기’로 이어 붙인 경우만 유지).
- 다시 풀기·모의고사에서 보던 문제 번호만 이 탭의 `sessionStorage`에 계정별로(`hanqacct:pos:<계정 ID>`) 남겨, 새로 고쳐도 그 문제로 돌아온다. 토큰·답은 저장하지 않는다.
  다시 풀기에도 ‘문제 바로 가기’(라벨 붙은 선택 상자)가 있고, 보기를 고르기만 해서는 채점하지 않는다(‘정답 확인’을 눌러야 서버 채점).
- 로그아웃: 이 탭의 로그인 정보는 언제나 지운다. 서버가 세션을 끊었는지 따로 알려, 연결 문제로 서버에 알리지 못했으면 “서버의 로그인이 남아 있을 수 있어요”라고 그대로 말한다.
- 가져오기 키는 저장소에 실제로 남을 때만 쓴다. 저장소를 쓸 수 없는 브라우저(막힘·용량 초과·저장이 안 남음)에서는 가져오기를 하지 않고 그 까닭을 보인다
  (부를 때마다 새 키가 생기면 ‘처음 가져간 계정에만’ 규칙을 지킬 수 없기 때문).

## 3. 저장소 키

- 학습 기록(`hanq:` 로 시작)은 읽기만 한다(가져오기 때). 이 기능이 쓰는 `localStorage` 키는 `hanqacct:signedIn`(로그인했던 흔적, 비밀 아님), 예전 `hanqacct:importKey`, 계정별 `hanqacct:ikey:<계정>`·`hanqacct:sync:<계정>`(동기화 키·확인 표시, 비밀 아님)이고, `sessionStorage`에는 계정별 문제 위치 `hanqacct:pos:<계정 ID>`만 둔다. 저장소 전체를 지우는 코드는 없다.

## 4. 주소

- `#account` · `#account/replay/<id>` · `#account/run/<id>`. 직접 열기·새로 고침·뒤로/앞으로 모두 같은 화면으로 열린다. 서버가 꺼져 있으면 모두 ‘서버 연결 꺼짐’ 안내.

## 5. 검사와 한계

## 6. 조정자 검증 (2026-10-08)

- 기존 전체 검사 8,126개 통과; 계정·클라이언트 검사 36개 통과.
- 실제 전용 Chrome 320/375/1280px: 가입·로그인, 개발용 테스트 이용권, 서버 오답 모의고사, 첫·끝·반복 이동, 답 보존, 44px 조작 영역 및 가로 넘침 검사. 원래 학습 저장소는 그대로 유지.
- 두 전용 탭의 실제 계정 전환 6개 검사 통과: A의 만료된 요청을 B로 재전송하지 않음, B 프로필 불변, A의 개인 내용을 즉시 지우고 B 화면으로 갱신.

- 프런트 API 주소는 기본 빈 값이며 실제 결제 제공자와 백엔드 배포 주소는 아직 정해지지 않음. 로컬 커밋만 수행하며 푸시·배포 없음.

배포 순서: `hanq_api` 진행 조회 엔드포인트를 먼저 배포하고 프런트를 배포한다. 이전 API에 대한 회원 진행 조회 실패는 안내·재시도로 처리하며 기기 기록으로 완료를 꾸미지 않는다. 기존 테이블·인덱스를 재사용하므로 추가 마이그레이션·기록 초기화는 없다.

## 7. 성장점수 보상 · 마이페이지 캐릭터(API 008·009 대기 중)
- 로그인한 회원(무료·프리미엄)의 보통 퀴즈 정답 +1·오답 −1, 기출 정답 +5·오답 −5는 서버가 채점과 같은 거래에서 기록한다. 화면은 채점 응답의 지금 총점(`growth.points`)을 같은 계정·같은 로그인(epoch)·내 정보 확인(ready)일 때만 반영해 헤더·마이페이지가 바뀐다(클라이언트는 점수를 계산하지 않음).
- CBT 결과 화면은 결과에 저장된 최종 점수 구간 보상(`growthReward`)을 보이고 내 정보를 한 번 다시 받는다(같은 계정·로그인일 때만). 문항별 보상은 없다.
- 성장점수 기록 창: 퀴즈 정답/오답(±1), 기출 정답/오답(±5), CBT 실전 최종 점수(−100·+50·+100·+150·+200). 허용 밖 점수가 섞인 쪽은 통째로 버린다.
- **마이페이지 캐릭터 열 번 누르기**: 관리자 기능이 아니고 보안 경계도 아니다. 기존 본인 전용·계정당 한 번 `POST /premium/test-free-pass`(서버 기능 표시 `HANQ_TEST_FREE_PREMIUM_ENABLED`, 006 기록)를 그대로 쓴다. 캐릭터는 키보드로 누를 수 있는 진짜 단추이고 숨은 안내 글은 없다. 열 번째에 한 번만: 공개 plan의 `testFreePass.available`이 true일 때만 요청하고, 요청 뒤 `/me`를 새로 받아 같은 계정·로그인에서 프리미엄이 켜져 있고 만료가 미래일 때만 말풍선 ‘프리미엄이 활성화되었습니다!’(이미 켜져 있던 체험이면 ‘이미 프리미엄이 활성화되어 있어요.’). 꺼짐·실패·끝난 예전 체험은 성공이라 하지 않고 다음 한 번 누름에서 다시 시도한다. 셈은 같은 로그인에서만 이어지고 로그아웃·계정 바뀜·새로 고침이면 처음부터. 오답노트 화면의 테스트 전환 단추도 같은 서버 규칙을 쓴다.
