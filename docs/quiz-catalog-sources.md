## 2. 문항을 합치는 규칙

- **기존 666문항은 한 글자도 바꾸지 않는다.** 앱의 원래 배열은 그대로 두고, 카탈로그는 각 문항을 `legacy-<장>-<번호 3자리>`(배열 순서)로 담으며 원래 `q`·`a`(별칭 전부)·`section`·`clue`·`why`·`cue`를 `legacy` 칸에 그대로 보관한다.
- **교재 642문항(check-GG-NN)**은 의미 대조표가 ‘같은 문제·같은 답’으로 확인한 기존 문항이 있으면 그 문항의 `sources`에 붙인다(조선 전기·후기에 같은 문항이 있으면 둘 다). 짝이 없는 문항만 `check-GG-NN` ID의 새 문항이 된다. 수(붙은 문항·새 문항·풀 크기)는 짐작하지 않고 생성기가 센 값을 카탈로그 `counts`와 지도에 적는다.
- 글이 같아도 **묻는 것이 다른 문항은 합치지 않는다**: check-05-06(왕: 법흥왕) ↔ check-06-21(국가: 신라), check-11-04(왕: 예종) ↔ check-15-01(침입한 세력: 여진), check-33-12(시기: 1920년대) ↔ check-34-08(정책 이름: 산미증식계획). 대조표가 서로 다른 기존 문항으로 이어 주고, 생성기는 둘이 한 문항으로 합쳐지면 멈춘다. 화면에는 ‘묻는 것 · 왕/국가/시기/…’를 따로 보인다.
- 교재 문항마다 원문 줄·번호·묶음 제목·원문 문제(`rawQuestion`)·원문 정답(`rawAnswer`)·쓰는 정답·정정·문맥 보완을 그대로 남긴다(카탈로그 `sources`, 감사용). 화면의 채점 뒤 출처 줄은 짧게 **‘교재 확인 문제 · 단원 · 묶음 n번 · PDF n쪽(교재 n쪽)’**만 보인다(쪽은 아래 4-1절대로 문제 줄이 실린 실제 쪽이 하나로 증명된 것만, 아니면 단원 · 묶음 · 번호까지만). 원문 행 수 · 깨진 원문 정답 · 문항/보기 ID · 해시는 화면에 내지 않는다. 정답 정정이나 문맥 보완이 있는 문항에만 접힌 **‘출처와 정정 기록’**이 붙어, 원래 표기 → 고친 표기와 근거 PDF 쪽을 보여 준다.
- **정답 정정 18건**(예: check-03-09 원문 ‘장수왕 ②→⑧→…’ → 장수왕, check-03-10 원문 빈칸 → ②→⑧→④→③→⑥→①→⑤→⑦, check-24-02 동의보감 → 동의보감(광해군), check-26-15 원문 끝의 조약 별칭 주석은 정답이 아님 → 조영통상조약): 교재 PDF 정답표 쪽과 함께 기록하고, 원문 정답은 지우지 않는다. 깨진 원문 정답은 보기·채점에 쓰지 않는다.
- **문맥 보완 4건**(check-21-08 ‘(국가) 두만강 일대를 개척하여 6진을 설치하였다’ 등): 원문은 행동한 나라(조선)로 읽힐 수 있어, 교재 PDF 72쪽 표대로 ‘조선이 … 상대했던 세력은?’으로 묻는다. 6진·무역소의 정답은 여진이고 ‘조선’은 보기에 넣지 않는다(생성기가 확인하고 멈춤).
- check-31-23은 원문에 앞 묶음의 정답이 잘못 붙어 있어(‘[동학농민운동] …’), 고친 문제 글을 화면에 쓰고 원문은 보관한다. check-31-22·23의 연도 붙은 정답은 기존 개화기 문항과 같은 순서라 기존 문항에 붙이고, 연도는 정답 풀이에만 보인다.

## 3. 보기 만드는 규칙

- 보기는 2–4개, 정답은 하나. **보기 ID = `o` + sha1(문항 ID + 보기 글) 앞 10자리**라 자리가 바뀌어도 같다. 문항 버전 `v`는 문제·묻는 것·보기 글의 해시.
- 화면에서는 보기 순서를 문항 ID·버전·시도 번호로 섞고(정답이 늘 첫째에 오지 않게), 그 순서를 상태에 보관한다. 채점은 자리 아닌 보기 ID로 한다.
- **하나짜리 답**: 같은 종류의 다른 답에서 고른다. 종류는 ① 문제 끝 꼬리표((왕)·(책)·(인물)·(제도/왕)…), ② 섞인 묶음(‘해당되는 내용을 쓰세요’)이면 문제 속 말(이 사람·이 단체·이 지역·이 조약·시대는?…), ③ 아니면 같은 묶음 제목(왕 · 국가 · 정부 · 시기 …) 순으로 정한다. 같은 묶음 → 같은 장 → 같은 시대 갈래(조선 전기·후기) 순으로 찾고, **정답의 모든 별칭·괄호 안 말**(예: 왜(일본)의 일본, 양사(사헌부,사간원)의 사헌부·사간원)과 겹치는 답, 같은 글의 다른 문항의 정답은 넣지 않는다. 같은 종류가 하나뿐이면 보기 둘(억지로 채우지 않음).
- **짝 답**((책/왕)·(제도/왕)·(전쟁/왕)·(인물/왕), 예: 동의보감(광해군), 균역법(영조)): 쪼개지 않고 한 보기. 오답도 같은 꼴로 만든다(같은 책·다른 왕, 다른 책·같은 왕). 풀이에서 ‘책은 맞지만 왕이 다름’을 짚는다.
- **순서 문제**(‘발생 순서대로’): 정답 차례를 바꾼 묶음(이웃 바꾸기 · 한 칸 건너 바꾸기 · 돌리기 · 뒤집기 중에서). 보기에 번호 항목은 문제 글에 모두 보인다. 연도는 보기에 넣지 않는다(정답이 드러나지 않게).
- **순서 없는 여러 답**(check-02-11 옥저·동예, 삼사 사헌부·사간원·홍문관, 복신·도침·흑치상지, 장인환·전명운 등): 순서만 바꾼 묶음은 정답과 같으므로 오답이 아니다. 오답은 하나 이상을 같은 종류의 다른 답으로 바꾼 같은 크기의 묶음이다.
- **칸이 정해진 여러 답**(‘정족산성에서 OOO, 문수산성에서 OOO ( , )’ → 양헌수, 한성근 · ‘OO과 ☆☆’ → 주현, 속현 · ‘○, ☆☆, △’ → 향, 부곡, 소): 칸을 바꾼 묶음이 오답.
- **짝짓기**(check-12-02, (2)-1 ②,③ / (2)-2 ⑤ / (2)-3 ④ / (2)-4 ①): 유효한 문항으로 그대로 둔다. 오답은 두 칸 사이의 번호 하나를 맞바꾼 짝. 같은 칸 안의 번호 순서(②,③ = ③,②)는 정답과 같다.

## 4. 보기별 풀이(공용 계약)

- 채점 뒤에만 보인다. 오답을 고르면 **모든 보기**에 풀이가 붙고, 고른 오답은 ×, 정답은 ✓로 구분한다. 좁은 화면에서도 풀이는 보기 바로 아래에 한 줄씩 쌓인다.
- 줄은 짧게, 핵심어는 굵게.
  - **정답 보기**: ‘결정 단서 **a**·**b** → 묻는 ○○의 정답’(결정 단서 = 교재 근거 줄과 겹친 문제 말, 없으면 문제의 긴 낱말) · 교재 근거 줄 · 같은 답의 다른 단서 · 기존 문항이 직접 쓴 풀이(정답을 되풀이하는 기본 문장은 뺌) · 교재 정답 표기. 정답을 선언만 하는 한 줄 풀이는 없다(검사기가 확인).
  - **오답 보기**: ‘이 문제의 답이 아니에요. 결정 단서 **a**는 **정답** 쪽’ + 그 보기가 실제로 무엇인지(그 답이 정답인 다른 문항의 단서, 없으면 그 이름이 나오는 교재 줄) + 흐름 카드에 있으면 그 보기의 흐름·왕/시기.
  - **짝 답 오답**(예: 송시열(순조)): ‘송시열까지는 맞지만 짝인 왕이 틀렸어요 → 교재 정답은 송시열(효종)’처럼 **맞는 짝으로 설명**하고, 보기의 가짜 짝(송시열·순조)을 사실처럼 쓰지 않는다. 바뀐 왕은 그 왕 자신의 단서를 따로 보인다(검사기가 가짜 짝 문장을 막음).
  - **순서 오답**: 처음 달라지는 자리, ‘**c**가 **w**보다 먼저’, 교재 정답에 연도가 있으면 그 연도만.
  - **묶음 오답**: 들어가면 안 되는 답(그 답의 실제 단서)과 빠진 답(교재 근거 줄). **칸 오답**: 칸마다 정답과 그 답의 교재 줄. **짝짓기 오답**: 달라진 칸.
- `media/quiz-review.js`의 `HanqQuizReview.contract(item, selectedOptionId)`(schema 2)는 문항 ID · 버전 `v` · 풀이 버전 `rv` · 고른 보기 · 정답 보기 · 문항 풀이 카드 · 보기마다 판정(correct / selected-wrong / other)과 풀이 줄 · 원문 출처(원래 기록 그대로)를 돌려준다. `renderOverview`는 카드, `render`는 카드 + 보기별 풀이 + 짧은 출처를 HTML로 그린다. 뒤에 만들 오답 노트·다시 풀기·마이페이지가 같은 계약과 그리기를 쓴다.

## 4-1. 문항 풀이 카드(overview, 703문항 모두)

채점 뒤(맞혀도 · 틀려도) 피드백 안과 결과 화면의 오답 노트에 하나씩 보인다. 칸은 `answer`(정답) · `ask`(묻는 것) · `reason`(왜) · `clue`(결정 단서) · `context`(흐름) · `memory`(외울 말) · `contrast`(헷갈림) · `refs`(근거).

- **왜**: 정답 이름이 실제로 나오는 교재 줄(또는 정답 이름만 있는 표 칸 줄의 위아래 3줄, 같은 쪽) 가운데 문제 말과 가장 많이 겹치는 줄. 확인 문제 쪽(‘(n) …’ 줄이 셋 이상인 쪽)은 같은 문제를 근거로 되쓰지 않으려고 뺀다. 그다음 기존 문항의 직접 쓴 풀이 · 교재 핵심 개념 행. 순서 문제는 올바른 차례(+ 교재 정답의 연도), 묶음·칸 문제는 답마다 교재 줄, 짝짓기는 칸별 짝.
- **흐름**: 정답 이름이 나오는 흐름 카드 문장(흐름 이름 › 덩어리(왕·시기): 문장), 짝 답이면 왕의 흐름도, 교재 핵심 개념 행, 같은 답의 다른 단서. 아무것도 없으면 범위(장 · 묶음 제목)만 적는다.
- **외울 말**: 정답 · (짝 답의 왕) · 결정 단서 · 흐름 카드의 암기 키워드 중 정답이 든 것.
- **헷갈림**: 다른 보기의 실제 단서(그 답이 정답인 다른 문항 · 교재 줄), 짝 답은 ‘X는 Y 때 — Z와 짝지으면 틀림’, 순서는 가장 먼저 어긋나는 두 항목. 없으면 흐름 카드의 ‘헷갈리지 않기’ 문장.
- **근거(refs)**: `textbook`(교재 줄 번호 · PDF 쪽 · 교재 쪽 · 표/절 제목) · `flow`(파일 · 흐름 · 덩어리) · `notes` · `legacy-why` · `catalog` · `confirm-answer` · `teacher`(강의 원고 행 번호만) · `confirm`(교재 확인 문제 ID · PDF 쪽). 화면에는 ‘근거 · 교재 n쪽(표 제목) · 흐름 카드 ‘…’ · 교재 핵심 개념 · 기존 풀이 · 강의’처럼 사람이 읽는 말만 보이고, 줄 번호·ID·파일 이름은 내지 않는다.
- **날짜·사실**: 카드와 풀이의 날짜는 교재 줄 · 흐름 카드 · 교재 정답에 적힌 것만이다. 생성기는 새 사실을 지어 쓰지 않고 이 자료들의 문장을 옮기기만 한다. 교재 근거 줄은 낱말 겹침으로 고른 것이라, 사람이 642문항의 사실을 하나하나 다시 확인했다고 주장하지 않는다.
- **교재 쪽 세기(고침)**: 교재 글은 144쪽 PDF(SHA-256 `35d850c6…`)를 pdftotext -layout으로 뽑은 것이라 쪽마다 쪽 나눔 문자 `\f`가 있다(144개, 빈 쪽도 셈). 줄 번호는 원래 글을 줄바꿈으로 나눈 그대로 두고, **줄의 PDF 쪽 = 그 줄 첫 글자 앞의 `\f` 수 + 1**(줄 안의 `\f`도 셈, 글자가 두 쪽에 걸친 줄은 쪽을 쓰지 않음), **교재 쪽 = PDF 쪽 − 7**(본문 PDF 8–144쪽에서만). 머리글·바닥글·차례 숫자는 쪽 세기에 쓰지 않는다.
  - 예전 방식(쪽 머리글 ‘Ⅱ고대…’를 세기)은 ‘Ⅲ 고려 시대’처럼 띄어 쓴 머리글을 놓쳐 Ⅲ부 뒤 모든 쪽이 PDF 39쪽(교재 32쪽)으로 얼어붙었고, 그 때문에 Ⅲ–Ⅶ부 전체가 ‘확인 문제 쪽’으로 잘못 분류되어 교재 근거 줄을 찾지 못했다(카드의 교재 인용 145문항뿐, 근거 약함 63문항). 예: 조프통상조약(check-26-14)·농상집요 문항에 PDF 39쪽이 잘못 붙었다. 이 인용들은 모두 버리고 새 방식으로 다시 만든다.
  - 생성기는 실제 PDF에서 확인한 그림 설명 8곳의 쪽이 맞아야만 진행한다: [연가7년명 금동여래입상] PDF 18 · [금동대향로] 21 · [기마인물형토기] 24 · [불국사 다보탑] 33 · [정혜공주 무덤의 돌사자상] 36 · [청자 어룡모양 주전자] 54 · [보은 법주사 팔상전] 77 · [김득신 파적도] 79(교재 쪽은 각각 −7). 하나라도 다르면 멈춘다.
  - 결과는 지도 `pagination`(방법 · \f 수 · 확인한 그림 설명 · 부별 PDF 쪽 범위 · 확인 문제 쪽을 찾은 수 / 하나로 증명 못 해 비운 문항)에 적힌다.
- **확인 문제가 실린 쪽**: 교재 글에서 ‘[ 묶음 제목 ]’ 아래의 ‘(번호) 문제 글 (   )’ 줄을 **번호 + 정규화한 문제 글 전체 + 묶음 제목**으로 맞춘다(원문 문제 글과 화면 문제 글 둘 다 시도). 후보가 여러 쪽이면 원문 단원(Ⅰ–Ⅶ)의 PDF 쪽 범위로 좁히고, 그래도 한 쪽으로 증명되지 않으면 **쪽을 비운다**(지어 쓰지 않음). 쪽이 있으면 `pdfPage` · `bookPage` · `textbookLine`(문제 줄)이 함께 남는다.
- **정정·문맥 보완의 쪽은 따로**: 정정 18건의 쪽(PDF 30·50·84·92·101)은 **정답표**를, 문맥 보완 4건의 쪽(PDF 72)은 **교재 표**를 확인한 쪽이라 원래 기록 그대로 두고, 화면의 접힌 기록에 ‘근거: 교재 정답표 PDF n쪽’ · ‘근거: 교재 표 PDF n쪽’으로 문제 쪽과 구별해 적는다.
- 카드의 교재 근거 줄은 그 문항 시대의 부(Ⅰ–Ⅶ) 쪽 범위에 있으면 가산해 고르고, 흐름 카드·핵심 개념이 없을 때는 같은 부에서 정답(묶음이면 그 답들)이 나오는 교재 줄을 흐름 칸에 쓴다. 범위 이름만 남는 카드는 지도 `overviewContextRangeOnly`에 모이고, 검사기는 그런 카드가 없어야 통과한다.
- **짝짓기 check-12-02**: 번호 짝만 보여 주지 않고, 교재 표의 구분 줄 넷 — (반무신) 김보당의 난·조위총의 난 · (농민) 김사미·효심의 난 · (천민) 만적의 난 · (특수행정구역) 망이·망소이의 난 — 을 교재 글에서 그대로 찾아 흐름 칸과 정답 풀이에 인용한다(못 찾으면 생성 중단).
- **묶음 정답**(삼사 · 장인환·전명운 · 김보당·조위총 · 망이·망소이 · 변발·호복 등): 답들이 한 줄에 함께 나오는 교재 줄, 답마다 교재 줄(같은 부 우선), 없으면 흐름 카드 문장을 붙인다. ‘모두 들어 있어야 정답’ 한 줄로 끝나지 않는다.
- 화면의 묶음 지시문은 객관식이라 ‘쓰세요·적으세요’를 ‘고르세요’로 바꿔 보인다(`HanqQuizReview.mcPrompt`). 카탈로그·문서의 원래 묶음 제목은 그대로다.
- 근거가 약한 문항(교재 줄 · 흐름 카드 · 핵심 개념 · 기존 풀이가 하나도 없는 카드)은 지도 `overviewWeak`에 모아 조정자가 화면에서 확인한다. 예전 63문항은 대부분 쪽 세기 오류로 Ⅲ–Ⅶ부 근거 줄을 찾지 못한 것이었다. 고친 뒤의 수는 생성 결과의 지도에 적힌다(이 문서는 수를 미리 적지 않는다).
- 검사기(18번)는 생성기의 쪽 계산을 되풀이하지 않고 따로 확인한다: 카드 인용의 교재 쪽 = PDF 쪽 − 7, 확인 문제 쪽이 한 쪽에 몰리지 않음(예전 PDF 39쪽 회귀 · check-26-14 · 농상집요·조프통상조약 카드), 정정·문맥 보완 쪽 원래대로, 지도의 그림 설명 8곳. `HANQ_CONFIRMATION_DIR`로 교재 원문이 있으면 검사기가 `\f`를 직접 세어 모든 카드 인용 줄과 확인 문제 줄의 쪽, 그림 설명 8곳을 다시 맞추고, 띄어 쓴 머리글 ‘Ⅲ 고려 시대’가 원문에 실제로 있음(예전 방식이 놓친 꼴)을 확인한다.

## 5. 화면(빈칸 탭)

- 탭·단계 번호·주소(`#chapter/<시대>/quiz`, 옛 `#chapter/joseon-early|joseon-late/quiz`)는 그대로. 탭 이름 ‘빈칸 N’의 N은 지금 고른 묶음의 문항 수.
- **문제 묶음**: 기본 20문항(예전과 같은 고르기, 조선 전체는 전기 20 + 후기 20 = 40) · 세트 1…⌈풀/20⌉(마지막 세트는 실제 남은 수) · 전체 풀. 풀 = 그 장의 기존 문항 전부(원래 순서) + 교재에만 있는 문항. 조선 전체 보기에서는 전기와 같은 문제·같은 답인 후기 문항을 한 번만 센다(각 부분 보기에서는 모두 보임).
- 보기를 고르면 임시 답만 바뀌고, ‘정답 확인’을 눌러야 한 번 채점한다. 같은 보기는 두 번 채점하지 않고, 틀려도 고른 답을 지우지 않는다(다른 보기를 고르면 다시 확인 가능). 맞히면 보기가 잠기고 1초 뒤 다음 문제로 — 그 사이 바로 가기·이동·묶음 바꾸기를 하면 넘김을 취소한다.
- 이동: 이전·다음 · 바로 가기(지금 묶음 안 번호 + 전체 풀 위치 + 채점 표시 ✓·×·○) · 처음 문제 · 안 푼 문제로 · 아무 문제나. 기록 지우기는 따로 있는 ‘이 묶음 기록 지우고 처음부터’ 버튼(과 결과 화면의 다시 풀기)으로만.
- 보기는 라디오 그룹(버튼 role="radio", aria-checked) · 누르기 44px 이상 · 초점 테두리 · 화살표 키로 보기 사이 이동 · 움직임 줄이기 설정이면 부드러운 스크롤 끔.
- 저장·계정·서버는 쓰지 않는다. 고르기·채점·묶음 바꾸기 때 `document`에 `hanq:quiz` 이벤트(문항 ID · 버전 · 보기 ID · 보기 순서 · 공용 풀이 계약)를 보내고, `window.HanqQuiz`가 읽기 전용 고리(지금 묶음 문항 · 상태 사본 · 보기 순서 · 풀이 계약)를 연다.
- 채점 전 용어 풀이는 문제 글에만 달고, 받는 답의 모든 별칭(기존 별칭 + 교재 정답 표기)이 들어간 풀이는 뺀다(기존 `noLeak` 그대로). 보기 글에는 풀이를 달지 않는다.

## 6. 낮은 확신 · 남은 한계

- 섞인 묶음에서 문제 속 말로 종류를 정하지 못한 문항은 같은 묶음의 다른 답을 보기로 쓴다(`flags: kind-from-group`, 지도 `kindFromGroup`). 예: ‘원 간섭기’ 묶음의 ‘변발, 호복’은 같은 종류의 다른 풍속이 자료에 없어 같은 묶음의 다른 답으로 바꾼 묶음이 오답이 된다. 그럴듯함이 낮을 수 있어 조정자의 화면 확인이 필요하다.
- 보기가 2–3개인 문항은 지도 `flags`(options-2·options-3)에 적힌다.
- 카드의 교재 근거 줄 · 오답 보기의 ‘이름이 나오는 교재 줄’은 낱말 겹침으로 고른다. 나라 이름(고구려·백제 …)처럼 교재에 자주 나오는 답은 문제와 상관이 적은 줄이 뽑힐 수 있어, `overviewWeak`와 함께 화면 확인이 필요하다.
- 맞히면 1초 뒤 다음 문제로 넘어가는 동작은 그대로라, 맞힌 문항의 카드는 바로 가기로 돌아오거나 결과 화면에서 다시 본다.
- 작성자는 생성기·검사기·브라우저를 실행하지 못했다. 실제 문항 수(교재만의 문항·풀 크기·모양별 수)와 보기 품질, 320·375·1280 화면, 키보드·화면 읽기 프로그램 동작은 조정자가 생성 뒤 확인해야 한다.
- 기존 ‘입력해서 맞히기’ 검사(42개)는 객관식으로 바뀌어 조정자가 따로 맞춘다. 이 단원에서 고친 검사기 동작 검사는 같은 뜻(입력 유지 → 고른 답 유지 등)으로 옮겼고 지우지 않았다.
