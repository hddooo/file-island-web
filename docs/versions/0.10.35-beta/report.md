Candidate only: this version is held on its feature branch until the API coordinator confirms qualification and deployment. The API contract is owned by the API repository; this frontend requires gradingVersion 2, supportedGradingVersions including 2 and gradingStorageScope isolated-v2 on every selected response. A stale, unsupported or malformed server response fails closed. No v1 write fallback or answer canonicalization is used.

New quiz entries remain blank and temporary until explicit final submission. Original values, checked slots, source digest, CAS revision and mutation identity are preserved. Final statistics and confetti use the acknowledged server result rather than an optimistic local result. Failed submission does not replace the last confirmed result. Existing v1 data is never migrated or overwritten: a separate previous-method saved-result card exposes its original statistics, wrong answers and PDF. v1 results are not silently mixed into v2 era-menu percentages or Uigeumbu counts. The current v2 storage still holds the latest submitted result; immutable multi-attempt history remains separate work.

The matcher uses 46 policies bound to source digest, item, answer, slot, order and normalized expected-answer hash. Full compound tokens remain required except for explicit alias syntax or audited context-specific optional explanations. Sequence behavior takes precedence; missing, duplicate and extraneous tokens do not become correct by stripping punctuation.
