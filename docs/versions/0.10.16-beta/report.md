# 0.10.16-beta report

## Delivered changes
Both the actual public `/auth/login.html` entry and in-app login/signup use the horizontal Digivice presentation, existing self-hosted pixel font, wide primary action, lower signup action, password visibility control, and animated File Island scenery. Mobile/low-landscape layouts remain scrollable. Reduced motion, hidden-tab, pagehide and low-power modes pause scenery.

The public gate is generated by `node scripts/build-auth-login.cjs`; use `--check` to verify freshness. Only existing decorative artwork/font bytes are embedded because `/media` remains member protected. No protected learning content, new browser permissions, cookie policy, nginx allowlist, backend contract or account-data changes are included.

## Verified before release
- 16 in-app browser scenarios: Chromium/WebKit at 320×740, 390×844, 1440×900 and 844×390, normal/reduced motion.
- 80 public-gate browser scenarios: the same engines/sizes and ten capability/login/signup/failure variants, including absent capability, unavailable retention, generic server failure and no Web Locks.
- 225 auth/account unit assertions and 36 frontend recovery/deployment tests passed. Member-access harness also passed.
- Login/signup/error screenshots inspected; form bounds, type, controls and desktop/mobile device framing checked. Motion advancement, pause and cleanup checked. The public gate makes zero protected-media requests.
- Generated HTML freshness, JavaScript syntax and `git diff --check` passed.
- Credential fixtures remained out of storage; CSRF, same-origin requests, shared cookie lock, explicit retention opt-in, return hash and manual retry preserved.

Tests use dedicated headless Chromium/WebKit, synthetic account/API fixtures and no user's Chrome. Commands: `node scripts/qa-auth-digivice.cjs`, `node scripts/qa-auth-gate.cjs`, `node scripts/test-remember-session.cjs`, `node scripts/test-member-access.cjs` plus existing auth/account and frontend-cd suites. Playwright resolves through the existing QA tooling; it is not a new runtime dependency.

## Remember-login finding and limits
The baseline server's public plan response does not declare 90-day remember support. This release fixes the public gate's misleading enabled checkbox and preserves ordinary login; it does not activate 90-day sessions. No real-account cookie longevity, real iPhone/Safari, or 90-day elapsed expiration verification is claimed.

The unrelated `test-cbt-auth-transitions.cjs` has a baseline `#fePause` null failure. `test-source-reauth-draft.cjs` requires an adjacent private API fixture and was not run. Neither was weakened or rewritten.
