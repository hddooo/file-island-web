# 역사 회사모드 사전검수

## 변경

- shared steps 및 고려/조선 topics/modes를 원본 선택 상태가 보이는 파일 탭으로 표시한다. 숨겨진 구형 toc 및 비활성 원문 메뉴는 노출하지 않는다.
- 모의고사 회차의 독립 시작/다시확인/오답만 스위치를 보존하면서 파일 행으로 표시한다.
- 오답 재풀이와 lazy details summary를 파일 행으로 표시하고, 흰 좌우면·굵은 테두리를 정리한다. 원래 오답 텍스트와 펼침 상태를 유지한다.
- legacy review toc의 data-group을 시대 data-id와 분리해 잘못된0개 헤더를 바로잡는다.
- 고려/조선 카드·문단·표 외부 여백을 적당히 줄인다. 이미지 전용 figure-group wrapper만 그림 없는 텍스트 흐름으로 바꾸며 caption/status를 보존한다. coordinate diagram, source timeline, source crop과 표 내부 너비/스크롤은 변경하지 않는다.
- body직속 이미지 설명도 회사모드 해제/역사 이탈 시 정리한다. 원본 media 노드/src/alt는 보존한다.

## 검수 범위

새 역사 DOM/CSS21개와 기존 메뉴8개·회사모드18개 독립 회귀(합계47개), 버전 빌더가 통과했다. 원본 handler·DOM identity·disabled·switch·lazy details·반복 복귀·숨김 제어·CSS scope를 검사한다. 전체 저장소 검사/실기기 검증으로 표현하지 않는다.

수정 전 실제 운영에서 역사 메인, 시대 선택, 회차10개, 오답76개, 선사 원문, 고려/조선 내부 메뉴를 확인했다. 조선 본문 카드에32px padding/24px margin이 남음을 확인했다.

선사 회사모드 첫 원문 로딩 중 Chrome 오류9가1회 발생했다. 일반모드 동일 원문 로딩, 회사모드 전환 및 회사모드 재접속을 다시 확인했을 때 정상이며 원인은 확정하지 못했다. 추정으로 loader/접근 가드를 변경하지 않았다.

모의고사 회차는 준비 확인 필요 상태였으므로 기존 disabled를 유지했다. 실제 신규 시험 시작·답안 제출·체크 저장은 하지 않았다.

## 운영

이 기록은 사전검수다. 정확 SHA CI/CD와 수정 후 실제 운영 메뉴/원문 확인은 별도 후속 단계다. 320/390 및 Safari/iPhone 실기기는 미검증이며 모든 페이지의 모든 상태를 완전검수했다고 주장하지 않는다.

### 후속 운영 검수와 저장소 알림 충돌

1b955f9a는 빌드·운영 배포가 성공했다. 운영 meta의 정확 SHA를 확인하고 Chrome 1180px/501px에서 공통 학습 단계, 고려/조선 주제와 모드, 모의고사 회차 및 오답 목록을 확인했다. 주제 전환, 빈칸 입력 유지, 오답 필터/펼치기/접기, 일반모드 원래 디자인 및 회사모드 재접속이 동작했다. 실제 시험 시작이나 답안 제출은 하지 않았다.

이 검수에서 기존 HPS storage listener가 회사모드와 probe 키 알림도 받아 다른 탭의 서버 오답노트를 구형 로컬 화면으로 덮는 문제를 발견했다. 이번 회사모드 CSS/파일 목록 변경 전에도 존재하던 경로다. 후속 수정은 index의 legacy HPS.onChange refresh에 기존 `.wn-panel` 소유 조건만 추가한다. 서버 CBT 노트와 로컬 노트의 소유권을 분리하며 학습 저장소, 수신 이벤트, 퀴즈/모의고사 복원 로직은 변경하지 않는다.

후속 커밋의 정확 SHA 빌드·배포와 cross-tab 운영 재검수는 별도로 확인해야 한다.

후속 저장소 충돌 회귀9개와 기존 회사/메뉴/역사47개(합계56개), 버전 빌더 및 index inline script 구문 검사가 통과했다. 새 테스트는 실제 index listener를 추출해 실행한다. company ON/OFF, probe, 학습 및 clear 이벤트가 HPS에는 그대로 전달되면서 서버 host는 유지되고, 기존 로컬 refresh/focus·풀이 중 상태·quiz/mock 복원이 계속 동작하는지 검사한다. 전체 저장소 검사라고 주장하지 않는다.

45c910d3의 빌드와 운영 배포가 성공했다. 정확 SHA 운영에서 다른 탭 새로고침, 회사모드 OFF/ON 후에도 서버 CBT 오답 host와 현재 문항 목록이 보존되고 native details 펼치기가 정상임을 확인했다. 일반모드 원래 스타일과 회사모드 파일 행도 각각 복원됐다.

### Practice 목록 폭 보완

독립 검수에서 회사모드 Practice Part 선택 버튼이 약24px로 눌리고 첫 행이 약310px로 늘어나는 문제를 확인했다. 회사 CSS가 원래 행을 flex로 바꾼 상태에서 PDF 도구의 width:100%가 남아 폭을 차지한 것이 원인이다. 회사모드의 `.tc-group-list[data-company-native-directory]>.tc-group-row`만 원래 한 열 grid 구조로 복원한다. Part 버튼과 PDF 도구의 소유권·상태·다운로드 및 일반모드는 변경하지 않는다. 후속 정확 SHA 배포와 1180px/501px 실제 너비 검수는 아직 완료로 표시하지 않는다.

목록 전용 회귀7개가 통과했다. 수정 없는 대조군의 flex 재현, CSS 로딩 순서 전/후 grid 승리, normal-off, 반복 복귀, Part/PDF 독립 핸들러와 disabled/hidden/상태, 비동기 목록 교체를 검사했다. 기존56개 회귀도 재실행해 통과했다. JSDOM 검사는 실제 너비/높이 또는 PDF 생성 성공을 검증하지 않는다.
