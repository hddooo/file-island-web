# TOEIC 단어·구문 노트

한국사 메인의 ‘토익 단어·구문 노트’와 `#toeic`에서 연다. 기존 `#toeic/lc/*`, `#toeic/rc/*` 주소도 이 노트로 연결한다. 기존 데모 풀이 코드는 실행하지 않는다. 한국사 경로·풀이 기록·채점은 변경하지 않는다.

- Part 1 / Part 2 / Part 3·4 / Part 5·6 / Part 7.
- 로그인 계정에 저장하며 게스트·초기 노트는 비어 있다. seed나 사용자 오답 예시는 없다.
- 표현, 뜻, 문장 구조, 짧은 예문, 혼동 표현, 원문, 출처/사진 이름을 직접 누적·편집한다. 사진 파일 업로드/OCR/자동 해설 생성은 이번 범위에 없다. 사용자가 전달한 사진/텍스트를 검토해 원문과 정리 내용을 입력할 수 있는 구조다.
- Part 필터와 전체 내용 검색. 같은 Part에서 NFKC·대소문자·연속 공백만 다른 표현은 중복 저장을 거절한다.
- 저장된 두 노트를 명시적으로 선택·확인해 합친다. 현재 표현/Part를 유지하고 내용과 출처를 덧붙이며 원래 표현/Part도 출처에 남긴다. source는 같은 거래에서 삭제한다. 편집 중인 내용은 먼저 저장해야 합칠 수 있다.
- revision으로 다른 탭의 편집을 덮어쓰지 않는다. 저장 불확실/경합 시 초안을 유지하며 목록을 새로 불러와 비교한다.
- 모든 내용을 textContent/value로 렌더링한다. 저장소에 인증 토큰을 기록하지 않는다. 기존 API 클라이언트의 소유자/세션 검증을 사용한다.
- 만료된 세션의 초안과 `#toeic` 복귀는 기존 HanqAuthSession의 30분·같은 소유자 정책을 사용한다. 로그아웃/다른 계정에서는 폐기한다. 일반 화면 이동 시 초안은 메모리로 보존하며 새로고침에는 미저장 경고를 띄운다.

검증: `node scripts/qa-toeic-notes-browser.cjs` (별도 `.test-tools/node_modules/playwright` 필요). headless Chromium, 390/1440px, 실제 전체 프런트와 API 클라이언트, HTTP만 픽스처로 격리. 운영 서비스에 통신하지 않는다.

배포: API의 `019_toeic_notes.sql` 추가 마이그레이션을 포함해 API를 먼저 배포하고 정상 응답을 확인한 뒤 프런트를 배포한다. API 시작 시 기존 migrator가 새 테이블과 비공개 스키마 권한을 같은 거래에서 적용한다. 운영 DB 테스트 데이터는 넣지 않는다.

## 단어 직접회상 연습 (사용자 지정 방식)

기본 화면은 ‘단어 뜻 적기’다. 영어 표현은 왼쪽, 한국어 뜻 입력은 오른쪽에 같은 행으로 놓는다. 모바일에서도 두 칸을 유지한다. ‘노트 관리 · 구문 설명’에서 기존 노트 편집과 병합을 그대로 사용한다.

- 사용자가 등록한 노트 중 뜻이 있는 항목만 연습한다. 초기 단어·예시·오답은 넣지 않는다.
- Part 필터별 생성일/ID의 안정된 순서로 최대 100개씩 나눈다. 1~99개는 실제 개수만, 101개는 100+1, 201개는 100+100+1이다.
- 정답 뜻·구문 설명·예문은 입력 전 DOM에 넣지 않는다. 입력 후 ‘정답 확인’ 또는 Ctrl+Enter로 확인하고 ‘기억했어요 / 다시 볼게요’를 직접 선택한다. 자동 완전일치 채점·정오 판정·점수는 없다.
- 입력 전 Tab/Shift+Tab은 다음/이전 뜻 입력으로 이동한다. 정답 확인 후에는 기본 Tab 순서로 자기평가 버튼을 쓸 수 있다. IME 조합 중에는 중간 입력 저장이나 Ctrl+Enter 확인을 실행하지 않는다.
- 뜻 입력·정답 확인 상태·자기평가는 단어별로 계정에 자동 저장한다. Part와 묶음 위치도 계정에 저장한다. 입력/평가 개수만 표시하며 정답률은 계산하지 않는다.
- 실패/동시 편집 시 입력을 유지하고 재시도를 제공한다. 저장 전 새로고침에는 경고한다. 세션 만료 시 기존 30분·같은 소유자 복원 정책으로 미저장 입력을 복원하며 명시적 재시도로 보관한다. 다른 계정/로그아웃에는 초안을 넘기지 않는다.
- 노트 내용을 수정하거나 병합하면 revision이 바뀌므로 옛 정답을 기준으로 한 연습 상태를 이어 쓰지 않는다. 병합된 source의 연습 데이터는 계정 복합 FK로 삭제된다.

추가 API/스키마: `toeic-recall`, `020_toeic_recall.sql`. 배포는 019·020을 포함한 API가 먼저다. 운영 배포는 아직 하지 않았다.

검증 스크립트:
- `node scripts/test-toeic-recall.cjs`: 0/1/99/100/101/200/201개 경계와 Part 필터·뜻 없는 노트 제외·안정 순서.
- `node scripts/qa-toeic-recall-browser.cjs`: 전체 프런트/인증 클라이언트 + 격리 HTTP 픽스처로 390/1440px, IME·Tab·정답 비노출·자기평가·저장/복원/계정 격리.
- `qa-toeic-recall-postgres.cjs`: 별도 승인된 폐기 가능한 loopback *_test DB에서만 실제 브라우저→Nest→PostgreSQL 검증. 테스트 도우미는 그 외 DB를 거절한다.

## 뜻 가리기와 문맥 필드

10/29 단어장 상단과 읽기 화면: Chapter 안에는 `← Chapter 목차`, 검색, `체크한 단어만 보기` 토글(누르면 `전체 보기`로 바뀌고 다시 누르면 현재 Chapter 전체로 복귀) 옆 체크 개수 배지(현재 Chapter 기준, 체크·해제 즉시 갱신), 눈 아이콘 뜻 토글(뜻이 보이면 열린 눈, 숨겨지면 빗금 눈, 접근성 이름·도움말은 다음 동작 `뜻 가리기`/`뜻 보기`)만 둔다. Chapter 안의 별도 `전체 단어 보기`·`PDF 저장·인쇄`·페이지 `← 뒤로`와 목차의 문법노트 이동 링크·이전 -ly 비교표 상자는 뺐다. 목차의 Chapter별 PDF·인쇄와 `전체 단어 보기`·`체크한 단어 보기`는 그대로다. 체크 칸은 항상 왼쪽 고정 열에 있고, 필터 전환과 뜻 숨김은 체크 목록을 저장하거나 바꾸지 않는다(체크·해제만 저장). 체크한 단어가 없으면 짧은 안내와 `전체 보기`를 보인다. 읽기 화면은 `media/vocabulary-reading.css`(단어장 host 전용): 단어 24/26px → 품사 태그 → 핵심 뜻 18px → 예문(영문 17px)·해석(16px) → 접힌 Tip, 한글은 픽셀 글꼴 대신 시스템 한글 본문체, 모바일 1열·760px 이상 2열(단어/읽기 열). 10/29 뜻 위치: 핵심 뜻은 단어·품사·형태 오른쪽에 둔다. 760px 이상은 단어 열(단어·품사·`-ing형`·동사 변화) | 뜻 열(뜻 아래에 예문·Tip)로 뜻이 단어와 같은 행에서 시작하고, 좁은 화면은 뜻 전체가 들어가면 같은 행 오른쪽, 안 들어가면 다음 줄 전체 폭으로 내린다(좁은 칸에 쪼개 넣지 않음). 단어 옆에는 품사 태그(명·동·형·부·전·접 등)만 둔다. 저장된 품사 칸의 `관용 표현`·`구문`·`조건 표현`·`불가산`·`가산`·`복수`·`[U, C]`·`holding=-ing형` 같은 설명은 단어 옆에 표시하지 않는다(저장 데이터는 그대로).

영어 표현→품사→문맥 뜻→동의·유사표현→영어 원문/번역 순서로 표시한다. 뜻 보기/가리기는 한국어 뜻·해석과 유사표현 힌트를 함께 제어한다. 영어 원문은 유지하고 목록/연습 전환 때도 한국어 답이 새지 않는다. 연습에서는 뜻을 입력한 뒤만 볼 수 있으며 숨겨도 기존 자기평가를 지우지 않는다. 출처 Part가 없으면 분류 미지정이며 임의 추정하지 않는다. 동의표현은 문맥별 유사표현이며 공식 빈출순위가 아니다. 추가 필드 마이그레이션022는 단어장 전용이며 CBT021은 이 배포에 없다.

10/29 추가: 단어장 목록의 페이지 나누기(`n / n 페이지 · N개`, 이전/다음, 페이지 선택)를 없애고 Chapter·전체·검색 결과를 한 목록으로 보인다(상태 줄은 `N개`/`검색 결과 N개`). 예문 출처 표기(`원문 예문 · …`, `출제문맥 · …`, `학습 예문 · 직접 작성`), `원문·출처`·`이전 예문` 상자, 오답 보기 설명 메모, 직접회상 연습의 출처 메모, PDF의 `표제어 사용 예문 미확인 · 아래는 관련 원문` 줄을 화면에서 뺐다. 저장된 출처 데이터와 편집 필드는 그대로다.
