# 나의 학습 기록 · 개인 랭크 계약 (media/activity-stats.js) — 단계 D

작성 2026-10-08. 나만의 오답노트(`#wrongnotes`) 맨 위의 ‘내 학습 기록’이다. 저장된 기록을 계산만 하고, 새로 저장하거나 채점하지 않는다.
이 브라우저 안의 개인 기록이다. 계정·서버·다른 기기 동기화·공개 순위가 없고, 저장소·시계를 손으로 고치는 것을 막는 보안 장치가 아니다.

## 1. 활동(잔디·오늘·정답률·연속 학습)

- **활동 1번 = 채점 기록(attempt) 1건**이다(`HanqProgress.store.attempts()`). 다음이 모두 활동이다.
  - 빈칸 ‘정답 확인’
  - 실전 모의 ‘정답 확인’
  - 오답 다시 풀기
  - 모의고사 회차의 최종 채점(문항마다 1건, 답하지 않은 문항 포함)
- 고르기·임시 답·웹툰 읽음 표시는 활동이 아니다.
- **과목**: 기본은 한국사(`history`)만 센다(`activity(…, {subject})`로 다른 과목을 고를 수 있게만 열어 둠). 과목이 없던 예전 기록은 한국사로 본다.
  - 다른 과목(예: toeic) 기록은 중복·날짜 모름을 세기 전에 먼저 빼서, 한국사 잔디·오늘·정답률·연속 학습에 섞이지 않는다.
  - 다른 과목 기록은 지우지 않는다.
  - 앱은 `HPS.attempts({subject:'history'})`로 읽는다.
- 같은 문제를 다른 때 다시 풀면 각각 센다(**풀이 수**). 서로 다른 문제 수는 `과목|종류|문항 ID`로 따로 센다(**서로 다른 문제**).
- 같은 제출의 중복은 저장소가 이미 하나로 줄인다. 같은 기록 ID가 두 번 와도 한 번만 센다.
- 날짜는 기록의 실제 시각(`ts`)을 **한국 시간(UTC+9, 서머타임 없음)**으로 바꾼 날이다. 기기 시간대와 관계없다. 자정·해 바뀜·윤년은 `Date` UTC 계산으로 처리한다.
- 시각이 없거나 범위를 벗어난 기록은 ‘날짜 모름’으로 따로 센다. 오늘이나 다른 날로 지어 넣지 않는다. 지금의 기록 형식은 시각이 꼭 있어서 보통 0이다.
- 잔디는 최근 70일(10주)이고 맨 끝이 오늘이다. 칸마다 단추로 되어 있고, 이름에 ‘날짜(오늘) · 풀이 n번 · 서로 다른 문제 · 맞힘’을 담는다. 누르면 같은 글이 상태 줄에 나온다.
- 색 단계는 0 · 1–2 · 3–5 · 6–9 · 10+번이고, 범례를 글자로도 보인다.
- 오늘 푼 문제(풀이 수와 서로 다른 문제), 정답률(맞힘 / 풀이 수), 연속 학습, 푼 날 수를 보인다.
  - 연속 학습: 오늘 풀었으면 오늘부터, 아직 안 풀었으면 어제부터 거꾸로 이어진 날 수.
- **오답 해결** = 지금 내용으로 다시 풀 수 있는 서로 다른 오답(아직 못 풂 + 해결) 중 해결한 수와 비율이다. 내용이 바뀌었거나 빠진·맞지 않는 옛 기록은 해결로 치지 않고, 빼고 따로 수를 알린다.
- 기록이 없으면 모두 0이고 그렇게 말한다(지어낸 잔디·숫자 없음).
- 다른 탭의 변경이 오면 나만의 오답노트가 다시 그려지면서 함께 다시 계산된다. 풀던 답은 건드리지 않는다.
- 저장 막힘·용량·깨진 기록·새 형식 기록은 저장소의 기존 처리와 알림을 그대로 쓴다. 새 형식 기록은 세지 않는다.

## 2. 개인 랭크

- 넣는 것: **순위 대상으로 명시된(`rankEligible:true`, `mode:'fixed'`) 날짜가 붙은 고정 미니 20·실전 50 회차의 처음 정해진 최종 결과**만이다.
  - 읽는 곳: `HanqRunUI.reader().finalResults({eligibleOnly:true})`(회차마다 결과 하나, 다시 채점하지 않음).
  - 순위 대상 여부는 회차 기록에 적힌 값만 보고, 이름·가격으로 짐작하지 않는다.
- 받는 결과의 조건(`eligibleFinal`). 맞지 않는 결과는 고쳐 넣지 않고 건너뛴다.
  - 상품: 상품 설정(`HanqRun.PRODUCTS` 한곳, 브라우저는 전역·Node는 `require('./run-controller.js')`·검사에서는 `rank(finals, {products})`로 넣음)에서 `mode:'fixed'`·`rankEligible:true`인 상품(지금은 `fixed-mini`·`fixed-formal`)이어야 한다.
  - 결과 자체도 `mode:'fixed'`·`rankEligible:true`여야 한다.
  - runId·submissionId·한국 날짜·시각이 있어야 한다.
  - 맞힘·틀림은 0 이상의 정수여야 하고, 합이 그 상품 문항 수(20·50)를 넘지 않아야 한다. 내용이 바뀌어 채점하지 않은 문항이 있으면 더 적을 수 있다.
  - 설정을 찾지 못하면 아무것도 받지 않는다.
- 회차마다: **+10 × 맞힘, −3 × 틀림**(답하지 않음은 틀림, 내용이 바뀌어 채점하지 않은 문항은 빼고). 회차를 더한 뒤 **0점 아래로 내려가지 않는다**. **레벨 = 1 + floor(랭크 점수 / 100)**.
- 시각 순으로 더한다. 같은 회차(runId)는 한 번만이라, 다시 제출·새로 고침·다시 들어오기로 늘릴 수 없다. 다른 회차는 각각 들어간다.
- 사건 id는 `rank-<submissionId>`, 규칙 버전은 `hanq-rank-1`이다.
- 0인 것:
  - 보통 빈칸·실전 모의·오답 다시 풀기: 기록·잔디에만 들어간다.
  - 개인 오답 모의고사: 늘 `rankEligible:false`, 복습용이다.
  - 웹툰 읽음
  - 앞으로의 가격(500·1000원): 랭크와 관계없다.
- 예전에 제안된 ‘연습 문제마다 +10/−3’은 쓰지 않는다. 보통 정답은 랭크 점수를 바꾸지 않는다.
- 이 랭크 점수는 한국사능력검정시험 문항 배점(1–3점)과도, 모의고사 결과의 HanQ 연습 점수와도 다르다. 화면에 규칙을 그대로 적는다.
- 순위 대상 회차는 ‘날짜별 모의고사’(`#exams`)에서 연다(`docs/run-controller-contract.md` 7-1). 각 준비 회차의 처음 회차만 순위 대상이다. 끝낸 뒤 ‘다시 풀기’는 `rankEligible:false`·`reviewOf`라 0이다. 아직 처음 결과가 없으면 랭크는 0이고, 화면에 그 까닭을 적는다.
- 이 규칙(+10/−3, 0 아래 없음, 100점마다 레벨)은 사용자가 따로 받아들인 공식이 아니라 HanQ의 제안이다. 화면과 이 문서에 그대로 적었다.

## 3. API

`HanqStats`(CommonJS로도 불러옴):
- `kstDay(ts)`, `addDays(day, n)`
- `activity(attempts, {now, days})` → `{today, total, correct, accuracy, uniqueQuestions, todayCount, todayUnique, todayCorrect, activeDays, streak, dateUnknown, cells:[{day, count, correct, unique, level, today}]}`
- `wrongResolution(notes)` → `{unresolved, resolved, excludedOld, total, rate}`
- `eligibleFinal(final, products)`
- `rank(finals, {products})` → `{points, level, nextAt, events:[{id, runId, title, kstDate, finalAt, correct, wrong, delta, before, after, rulesVersion}], rules}`
- `RANK_RULES`, `level(n)`

모두 시계를 넣을 수 있는 순수 계산이다.

## 4. 앞으로의 상품(계획만)

상품의 문항 수·시간·앞으로의 가격은 `HanqRun.PRODUCTS` 한곳에 있다(개인 미니 20문항 30분 500원, 개인 실전 50문항 80분 1000원, 채점·풀이·오답 정리 포함). 지금은 결제·로그인·유료 표시·무료 기능 막기·주문이 없고, 가격은 랭크와 관계없다. 실제 판매 전에는 서버 주문에 그때 가격을 남기고 권리 확인을 해야 한다.

## 5. 검사

- `node scripts/test-activity-stats.cjs`:
  - 한국 자정·해 바뀜·윤년, 같은 ID 중복, 같은 문제 다시 풀기, 날짜 모름, 연속 학습, 빈 기록, 오답 해결.
  - 랭크: 개인·보통 0, 처음 결과만, 같은 회차 두 번은 한 번, 두 번째 회차는 따로, 0 아래 없음, 레벨 전환.
  - 실제 저장소·회차 컨트롤러로 고정 미니 135점, 새로 고침 유지, 다른 탭·새 형식·막힌 저장소.
- `scripts/verify-hanq.cjs`: 처음 화면(잔디 70칸 모두 0, 랭크 0과 규칙, 범례 글자, 칸 누르기).
- 작성자는 실행하지 못했다. 실제 휴대폰 화면·한국 날짜 비교는 조정자가 확인한다.
